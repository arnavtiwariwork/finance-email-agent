# Finance Credit Follow-Up Email Agent

## Project Overview
An AI-powered agent that automatically generates personalised follow-up emails for overdue invoices. The agent reads invoice data, determines the correct escalation stage based on days overdue, and uses an LLM to generate professional, tone-appropriate emails for each debtor.

Built for: Finance Team Automation Hackathon — Task 2

---

## How It Works
1. Agent reads overdue invoices from CSV
2. Calculates days overdue and assigns escalation stage
3. Sends invoice details to LLM with tone instructions
4. LLM generates a personalised email
5. Email is logged with timestamp and status
6. Escalated records (30+ days) are flagged for human review

---

## Tone Escalation Matrix

| Stage | Days Overdue | Tone | Action |
|-------|-------------|------|--------|
| 1st Follow-Up | 1-7 days | Warm & Friendly | Pay now link |
| 2nd Follow-Up | 8-14 days | Polite but Firm | Confirm payment date |
| 3rd Follow-Up | 15-21 days | Formal & Serious | Respond within 48hrs |
| 4th Follow-Up | 22-30 days | Stern & Urgent | Pay immediately |
| Escalation Flag | 30+ days | Human Review | Assign to finance manager |

## Tech Stack & Decision Log

| Layer | Choice | Reason |
|-------|--------|--------|
| LLM | LLaMA 3.3 70B via Groq | Free tier, fast inference, strong instruction following |
| Agent Framework | Custom Python | Lightweight, full control, no framework overhead |
| Data Source | CSV via pandas | Simple, portable, no database setup needed |
| Email Send | Dry-run mode / SendGrid ready | Safe for testing, production-ready when needed |
| Logging | JSON audit file | Human-readable, easy to inspect, no database needed |
| Environment | python-dotenv | Secure key management |

### Why Groq + LLaMA over alternatives?
- **vs GPT-4o**: Groq is free, GPT-4o requires paid credits
- **vs Gemini**: Groq has no strict rate limits on free tier
- **vs Claude**: Anthropic free tier has very low quota
- **LLaMA 3.3 70B**: Strong reasoning, follows JSON output instructions reliably

### Why Custom Agent over LangChain?
- LangChain adds complexity without benefit for this linear workflow
- Full visibility into every step — easier to debug
- Lighter dependencies — faster setup for graders/reviewers

## Security Mitigations

| Risk | Description | Mitigation |
|------|-------------|------------|
| API Key Exposure | Keys leaked in code | .env file + python-dotenv, .env in .gitignore |
| Prompt Injection | Malicious input manipulating agent | Structured JSON output, output validation |
| Data Privacy / PII | Invoice data contains personal info | Local processing only, no PII in logs sent to cloud |
| Hallucination Risk | LLM generating wrong email content | Structured JSON output enforced, all fields from data source |
| Unauthorised Access | Anyone triggering the agent | API key authentication on Groq endpoint |
| Email Spoofing | Emails from wrong sender | DRY_RUN mode in testing, SendGrid verified sender in production |
| Accidental Live Send | Emailing real clients during testing | DRY_RUN=true by default in .env |

## Email Personalisation

Every email generated by the LLM contains:
- Client name (addressed by first name)
- Invoice number
- Exact amount due in Rs.
- Original due date
- Number of days overdue
- Payment link
- Tone matched exactly to escalation stage

The LLM is never allowed to generate generic content — all fields are injected from the data source.

## Escalation Cap

After Stage 4 (30+ days overdue), the agent automatically:
- Stops sending automated emails
- Flags the record as ESCALATION
- Logs it for manual finance/legal review
- Assigns to finance manager

## Developer Notes

- To switch to LIVE email sending: set DRY_RUN=false in .env and configure SendGrid
- To add more invoices: edit data/invoices.csv
- To change escalation thresholds: edit ESCALATION_STAGES in config.py
- Prompt iterations are documented in email_generator.py comments
